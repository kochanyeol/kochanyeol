# Django 학습 정리

## 1. Django 프로젝트 세팅

### 가상환경이 필요한 이유

프로젝트마다 다른 버전의 패키지를 사용할 수 있어서 각 프로젝트를 독립적으로 관리하기 위함

```
프로젝트 A → Django 4.0
프로젝트 B → Django 5.0
→ 가상환경 없으면 버전 충돌 발생
```

### Poetry란?

가상환경 + 패키지 관리를 동시에 해주는 도구

기존 방식

```bash
python -m venv venv
pip install django
pip freeze > requirements.txt
```

Poetry 방식

```bash
poetry init
poetry add django
```

pyproject.toml 파일 하나로 패키지 목록이 자동 관리됨

### 프로젝트 구성

```bash
django-admin startproject config .   # 프로젝트 생성
python manage.py startapp todo       # 앱 생성
```

### settings.py 경로 설정

templates 경로

```python
TEMPLATES = [
    {
        'DIRS': [BASE_DIR / 'templates'],
    }
]
```

static 경로

```python
STATIC_URL = 'static/'
STATICFILES_DIRS = [BASE_DIR / 'static']
```

media 경로

```python
MEDIA_URL = 'media/'
MEDIA_ROOT = BASE_DIR / 'media'
```

## 2. Database Model

### 모델이란?

파이썬으로 데이터베이스 테이블 구조를 정의하는 것

```python
class Todo(models.Model):
    title = models.CharField(max_length=100)
    content = models.TextField()
    is_done = models.BooleanField(default=False)
    created_at = models.DateTimeField(auto_now_add=True)
    user = models.ForeignKey(User, on_delete=models.CASCADE)
```

### 주요 필드 종류

| 필드 | 설명 |
|------|------|
| `CharField` | 짧은 문자열, max_length 필수 |
| `TextField` | 긴 문자열 |
| `IntegerField` | 정수 |
| `BooleanField` | True / False |
| `DateTimeField` | 날짜 + 시간 |
| `EmailField` | 이메일 형식 문자열 |
| `ImageField` | 이미지 파일 |
| `ForeignKey` | 다른 테이블 참조 (1:N) |
| `ManyToManyField` | 다른 테이블 참조 (N:M) |

### 주요 필드 옵션

| 옵션 | 설명 |
|------|------|
| `max_length` | 최대 글자수 |
| `unique=True` | 중복 불가 |
| `blank=True` | 공백 허용 |
| `null=True` | NULL 허용 |
| `default=` | 기본값 설정 |
| `auto_now_add=True` | 생성 시 자동으로 현재 시간 저장 |
| `auto_now=True` | 수정 시 자동으로 현재 시간 저장 |

### Migration

```
models.py 수정  →  makemigrations  →  migrate
(설계도 변경)      (변경사항 기록)     (DB에 실제 반영)
```

git으로 비유하면

| Migration | Git |
|-----------|-----|
| `makemigrations` | `git add + commit` |
| `migrate` | `git push` |

Migration이 필요한 이유

1. DB에 반영 전 검토 가능, 문제 있으면 삭제 후 재작성
2. 변경 이력이 파일로 남아서 추적 가능
3. 팀원과 migration 파일 공유 시 같은 DB 구조 유지 가능

```bash
python manage.py makemigrations  # 변경사항 기록
python manage.py migrate         # DB에 실제 반영
```

## 3. Jinja (Django 템플릿 언어)

### 템플릿 언어가 필요한 이유

HTML은 정적이라 고정된 텍스트만 표시 가능
템플릿 언어를 사용하면 HTML 안에서 Python 변수와 로직을 사용할 수 있음

```html
<!-- 템플릿 언어 없이 -->
<h1>안녕하세요</h1>

<!-- 템플릿 언어 사용 -->
<h1>안녕하세요 {{ user.name }}님</h1>
```

### 기본 문법

변수 출력

```html
{{ user.name }}
{{ todo.title }}
```

조건문

```html
{% if user.is_authenticated %}
    <p>로그인 중</p>
{% else %}
    <p>로그인이 필요합니다</p>
{% endif %}
```

반복문

```html
{% for todo in todos %}
    <p>{{ todo.title }}</p>
{% endfor %}
```

| 문법 | 용도 |
|------|------|
| `{{ }}` | 변수 출력 |
| `{% %}` | 로직 (if, for, block 등) |

### extends / block

부모 템플릿 (base.html)

```html
<!DOCTYPE html>
<html>
<body>
    {% block content %}{% endblock %}
</body>
</html>
```

자식 템플릿 (signup.html)

```html
{% extends 'base.html' %}

{% block content %}
    <h1>회원가입</h1>
{% endblock %}
```

| 문법 | 설명 |
|------|------|
| `extends` | 부모 템플릿 가져오기 |
| `block` | 부모에서 정의한 빈 공간을 자식이 채우기 |

## 4. FBV (Function Base View)

### FBV란?

함수를 기반으로 작성하는 뷰
요청(request)을 받아서 응답(response)을 반환하는 함수

```python
def todo_list(request):
    if not request.user.is_authenticated:
        return redirect('login')
    todos = Todo.objects.all()
    return render(request, 'todo_list.html', {'todos': todos})
```

### FBV vs CBV

| | FBV | CBV |
|---|---|---|
| 장점 | 직관적, 흐름이 한눈에 보임 | 반복 코드를 Django가 자동 처리 |
| 단점 | 기능 많아질수록 코드가 길어지고 중복 발생 | 내부 동작 파악이 어려울 수 있음 |

### render

HTML 파일을 만들어서 브라우저에 보내주는 함수

```python
render(request, 'template.html', {'key': value})
#      ↑         ↑                ↑
#   요청 객체   템플릿 경로       템플릿에 넘길 데이터
```

### redirect

다른 URL로 이동시키는 함수

```python
redirect('url_name')       # URL 이름으로 이동
redirect('/todo/list/')    # 직접 경로로 이동
```

## 5. URLs

### URL이란?

브라우저가 요청하는 주소와 뷰를 연결해주는 것

```
http://127.0.0.1:8000/todo/list/
                      ↑
                   이 경로를 처리할 뷰를 urlpatterns에서 찾음
```

### URL 분리의 필요성

분리 전 - config/urls.py에 전부 작성

```python
urlpatterns = [
    path('todo/list/', todo_list),
    path('todo/create/', todo_create),
    path('todo/delete/', todo_delete),
    path('accounts/login/', login),
    path('accounts/signup/', signup),
    # 앱이 많아질수록 계속 길어짐...
]
```

분리 후 - 앱별로 urls.py 관리

```python
# config/urls.py
urlpatterns = [
    path('todo/', include('todo.urls')),
    path('accounts/', include('accounts.urls')),
]

# todo/urls.py
urlpatterns = [
    path('list/', todo_list, name='todo_list'),
    path('create/', todo_create, name='todo_create'),
]
```

### 핵심 개념

| 개념 | 설명 |
|------|------|
| `urlpatterns` | URL 패턴 목록 |
| `path()` | URL과 뷰를 연결 |
| `include()` | 다른 urls.py를 가져와서 연결 |
| `name=` | URL에 이름을 붙여서 코드에서 참조할 때 사용 |

name을 사용하면 URL이 바뀌어도 코드를 수정할 필요가 없음

```python
# URL 직접 사용
return redirect('/todo/list/')

# name 사용 (권장)
return redirect('todo_list')
```
